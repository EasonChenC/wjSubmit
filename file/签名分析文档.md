## 二、关键请求详细分析

### 2.1 Request 1: 阿里云日志上报

**请求URL**:
```
https://sojump.cn-hangzhou.log.aliyuncs.com/logstores/activitypostdata/track
```

**请求方法**: POST

**请求体**:
```json
{
  "__logs__": [{
    "a": "373472784",
    "nonce": "42236a20-36c0-4901-b867-254485b2d0c3",
    "type": "3",
    "pd": "1$1}2$1}3$北京-东城区}4$2}5$1}6$2}7$1!1,2!2,3!2,4!3,5!2,6!2}8$3}9$1|2|3|5}10$2}11$6}12$1,2,4,3,5,6}13$232231}14$132121212"
  }]
}
```

**字段解析**:
- `a`: 问卷活动ID (373472784)
- `nonce`: 随机UUID，用于防重放攻击
- `type`: 日志类型 (3=提交数据)
- `pd`: **答案数据压缩格式** - 使用自定义分隔符压缩所有答案
  - `}` 分隔不同题目
  - `$` 分隔题号和答案
  - `|` 分隔多选题的多个选项
  - `!` 分隔矩阵题的多个子项
  - `,` 分隔排序题的顺序

**响应**: 200 OK (空body)

**作用**: 数据埋点，用于统计分析，**非必需**，可忽略

## 三、签名机制分析

### 3.1 jqsign签名参数

**原始签名值**:
```
71105b13.05%603.7%3A32.a%3B54.1677%3B6a1g3%600
```

**URL解码后**:
```
71105b13.05`03.7:32.a;54.1677;6a1g3`0
```

**签名特征分析**:
- 长度: 41个字符
- 格式: 多段由 `` ` ``, `.`, `:`, `;` 分隔的字符串
- 字符集: 十六进制 + 数字 + 特殊字符
- 可能的组成:
  - `71105b13` - 可能是时间戳或会话ID的哈希
  - `05` - 计数器
  - `03.7:32.a;54.1677;6a1g3` - 混淆的数据
  - `0` - 结束标志

**签名算法推测**:
1. **时间戳混淆**: 使用 `cst` 和 `t` 参数
2. **随机数混淆**: 使用 `rn` 和 `jqnonce`
3. **数据指纹**: 可能包含答案数据的哈希
4. **客户端指纹**: 可能包含User-Agent或其他浏览器特征

### 3.2 comsign签名参数

**签名值**:
```
AED3A9F20ED7CB1299D9A24D08242876AE27F586
```

**签名特征**:
- 长度: 40个字符
- 字符集: 十六进制 (0-9, A-F)
- **格式: 标准SHA1哈希**

**签名内容推测**:
可能是以下内容的SHA1哈希:
- 提交记录ID + 时间戳 + 随机数
- 答案数据 + 活动ID + nonce
- 服务端生成的签名 (用户无法伪造)

### 3.3 tvd加密令牌

**令牌值**:
```
1cEKl90uT4Q=
```

**特征**:
- Base64编码 (有尾部 `=` 填充)
- 解码后长度: 9字节
- 可能内容: 时间戳、用户ID、会话标识

## 四、验证机制总结

### 4.1 客户端验证

1. **必填项验证**: JavaScript验证所有14个问题已填写
2. **格式验证**: 文本长度、选项数量等
3. **排序题验证**: Q12必须点击全部6个选项
4. **隐藏字段验证**: Q10/Q11必须通过UI点击设置

### 4.2 服务端验证

1. **时间戳验证**:
   - `starttime` 和 `cst/t` 的时间差必须合理 (30-300秒)
   - 过快提交会被标记为机器人

2. **随机数验证**:
   - `jqnonce` 必须是有效的UUID格式
   - `rn` 随机数用于防重放

3. **签名验证** (关键):
   - `jqsign`: 客户端生成的签名
   - `comsign`: 服务端生成的签名
   - **如果签名校验失败，提交会被拒绝**

4. **数据完整性验证**:
   - `submitdata` 格式必须正确
   - 答案数量必须匹配题目数量

5. **验证码验证**:
   - `capt` 参数标识验证码状态
   - 当前问卷 `useAliVerify=0` (未启用)

## 六、关键发现

### 6.1 ✅ 好消息

1. **签名由页面JS自动生成**:
   - 我们**不需要手动实现签名算法**
   - 只要使用Playwright正常触发提交，页面JS会自动生成所有必需参数

2. **提交流程简单**:
   - 填写表单 → 点击提交按钮 → 页面JS处理一切

3. **验证码未启用**:
   - 当前问卷 `useAliVerify=0`
   - 短期内无需处理验证码

### 6.2 ⚠️ 需要注意的点

1. **必须等待页面JS执行完成**:
   - 提交前确保页面完全加载
   - `await page.wait_for_load_state('networkidle')`

2. **必须使用jQuery触发提交**:
   - ✅ 已实现: `await page.evaluate("$('#ctlNext').trigger('click')")`

3. **答题时间必须合理**:
   - 建议: 30-120秒
   - 过快会被检测

4. **批量提交必须使用代理池**:
   - 单IP提交过多会被封禁
   - 建议: 每IP每小时 <10次
